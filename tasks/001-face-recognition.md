# 001. Распознавание лиц на сайте

Статус: новое
Ветка: `feat/face-recognition`
Миграция: **0029** (другой номер не брать)
Требования: Ф2, П2, П5, Ф7, НФ1, НФ3, НФ4, ADR-0006
Автор задания: основной агент, 2026-11-02

## Зачем

Сейчас на сайте фото отмечают только вручную. Движок распознавания уже есть, но в платформу не встроен. Нужно, чтобы:
1. мама дала согласие на распознавание и загрузила 1–3 фото ребёнка;
2. вожатая или информатор загрузили пачку фото, а сайт сам подсказал «Похоже, это Даня»;
3. человек подтвердил подсказку, и она стала отметкой;
4. мама в ленте увидела на фото полупрозрачную рамку с именем вокруг своего ребёнка.

Правило персон: Татьяне меньше искать своего сына, Ане меньше ручных отметок.

## Что уже есть (прочитать перед началом)

- `docs/FACE_RECOGNITION_REPORT.md`: стек, замеры, риски.
- `backend/app/faces/engine.py`: `FaceEngine(models_dir).faces(bytes)`, `.sample(bytes)` (ровно одно лицо, иначе `FaceError("no_face" | "many_faces")`), `best_matches(faces, samples)`, `seal`/`unseal` (Fernet, ключ `settings.face_key`). Детектор под `threading.Lock`.
- Модели: `uv run python scripts/fetch_face_models.py models` (из `backend/`). В Docker скачиваются при сборке в `/app/models`, переменная `FACE_MODELS_DIR`.
- Фото дня: миграция `0028_photos.py`, модуль `backend/app/photos/`, экран `web/src/pages/Photos.tsx`. В `photo_tags.source` уже разрешено `'suggested_confirmed'`.
- Согласие на распознавание уже существует: вид `'biometrics'` в `data_consents` и `family_consents`, на сайте пункт «Распознавание на фото» в `web/src/pages/ConsentsPanel.tsx`.
- Как в 0028 строится `app.photo_consent_active` из правила 0025 (отзыв побеждает, блок 0027 после выхода из семьи). Для биометрии сделать так же: `app.biometrics_consent_active(child)`.
- Рамка: стиль и поведение в `backend/scripts/face_demo.py`, строка `PREVIEW` (классы `.frame.known`, `.label`, анимация, клик скрывает рамки, `prefers-reduced-motion`). Утверждено пользователем: полупрозрачное белое стекло, **без зелёного, без процента сходства, только имя**, рамка только у узнанного ребёнка.
- Как гонять тесты и ловушки параллельной базы: `backend/CLAUDE.md` (строки про `camp_test` и `CU_TEST_DATABASE_URL`).

## Что сделать

### База (миграция 0029)

- `face_samples`: `id`, `camp_id`, `session_id`, `child_id`, `embedding bytea` (только зашифрованный вектор), `created_by`, `created_at`, `expires_at` (конец смены). Само фото образца **не хранить**: после получения вектора байты выбрасываются.
- Не больше 3 образцов на ребёнка.
- `photo_faces` (подсказки): `photo_id`, `camp_id`, `child_id`, рамка в долях кадра (`x`, `y`, `w`, `h` от 0 до 1), `status` (`pending` | `confirmed` | `rejected`), `decided_by`, `decided_at`. Процент сходства в API не отдавать.
- У подтверждённой отметки должна сохраниться рамка, чтобы показать её маме.
- RLS на обе таблицы, `camp_id` обязателен. Роль `app_user` не читает `embedding` вообще. Работа только через `SECURITY DEFINER` функции по образцу 0028.
- Загрузить или удалить образец может только взрослый семьи этого ребёнка при активном согласии `biometrics`. Сотрудник лагеря образцы не загружает и не видит.
- Отзыв согласия `biometrics` сразу удаляет образцы ребёнка и его неподтверждённые подсказки. Подтверждённые отметки остаются как обычные, без рамки.
- После конца смены образцы удаляются: функция `app.purge_face_samples()` плюс скрипт `scripts/purge_face_samples.py`.
- Аудит: загрузка, удаление и очистка образцов пишутся в `audit_log`, без самих векторов.

### Сервер

- `POST /family-children/{id}/face-samples` (multipart, 1 файл): ошибки `no_face` и `many_faces` с понятным текстом. Ещё `GET` (только количество и даты) и `DELETE` для всех образцов.
- После загрузки пачки фото распознавание идёт **в фоне** (`BackgroundTasks` + `asyncio.to_thread`), а не в обработчике запроса: CPU-работа не должна блокировать сервер.
- Сравнивать только с детьми этого отряда, у которых есть активное согласие и образцы.
- `GET /squads/{id}/photos` отдаёт подсказки по каждому фото. Видят вожатые отряда и информатор.
- `POST /photos/{id}/faces/{face_id}/confirm` создаёт отметку с `source='suggested_confirmed'`. `/reject` её отклоняет.
- Лента родителя (`/me/photos`, `/photos/{id}`) отдаёт рамку **только для своих детей**. Рамки чужих детей не уходят на клиент.
- Движок создавать один раз на процесс (лениво). Если моделей нет, распознавание отключено, а ручные отметки работают (НФ3: отказ ничего не ломает).
- Сгенерировать `docs/openapi.yaml` и `web/src/api/schema.d.ts` штатными командами.

### Сайт

- Мама, карточка ребёнка, рядом с согласием «Распознавание на фото»: блок «Фото для распознавания». Загрузить до 3 фото, видно, сколько загружено, есть кнопка «Удалить все». Без согласия блок объясняет, что нужно сначала дать согласие.
- Вожатая и информатор, `Photos.tsx`: на фото подсказки «Похоже, Даня» с кнопками «Да» и «Нет». После «Да» появляется обычная отметка.
- Мама, лента и просмотр фото: рамка как в `face_demo.py`. Клик или Enter по фото скрывает и показывает рамки. Подпись только с именем. Учитывать `prefers-reduced-motion` и ширину 390 px.
- Тексты простые, к родителю на «вы», без длинных тире.

## Чего не делать

- Не хранить исходные фото образцов и не отдавать векторы ни на клиент, ни в логи.
- Не показывать процент сходства.
- Не публиковать и не отмечать ничего автоматически: только подсказка, решает человек.
- Не менять порог 0.363 и устройство движка без записи в отчёте.
- Не класть в репозиторий реальные фото людей. Для тестов подменить движок фейком с заранее заданными векторами.
- Не трогать миграции 0001–0028.

## Тесты (обязательно)

- Чужой родитель не может загрузить, прочитать или удалить образец чужого ребёнка.
- Без согласия `biometrics` образец не принимается. После отзыва образцы и подсказки удалены.
- Сотрудник не читает `embedding` ни через API, ни через прямой `select` под `app_user`.
- Подсказки создаются только для детей отряда с согласием и образцами.
- confirm создаёт отметку `suggested_confirmed`, reject не создаёт.
- В ленте мама видит рамку только своего ребёнка. Рамки чужих детей в ответе нет.
- Очистка после смены удаляет образцы.
- Без моделей загрузка фото и ручные отметки работают.
- Web: тесты логики рамок и подсказок по образцу `web/src/lib/photos.test.ts`.
